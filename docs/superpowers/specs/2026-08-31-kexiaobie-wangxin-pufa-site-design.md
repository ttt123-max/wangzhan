# 法治先锋——"科小獬"网信普法新模式探索者 网站设计文档

> 版本：v1（第一版）
> 日期：2026-08-31
> 状态：待评审

## 1. 概述

"科小獬"是一个以 IP 形象为核心的全场景网信普法网站。它不是简单陈列法律条文，而是围绕 IP 形象"科小獬"（科大 + 司法元素，獬豸法治神兽）展开科普、互动问答与答题积分体系。用户可阅读普法专栏、访问线上普法驿站、按主题/案例类型筛选，并输入关心的网络法律问题，系统结合科小獬 IP 输出对应的普法解读。

第一版目标是交付一个可上线运行的完整站点，具备真实的用户账号与数据持久化，满足普法内容浏览、互动问答、答题赚积分、积分解锁拓展专题的基础闭环。

## 2. 目标与成功标准

### 业务目标

- 以"科小獬"IP 建立网信普法的品牌辨识度，覆盖 8 个核心普法专题。
- 新用户无需付费即可访问全部基础普法内容。
- 通过小问答赚取积分，积分可解锁"拓展案例专题"，形成"学 - 练 - 解锁"的正向闭环。
- 用户可输入网络法律问题，获得贴合 IP 口吻、内容准确的普法解读。

### 成功标准（v1）

- 用户可完成注册、登录并浏览基础内容。
- 用户完成答题获得积分，积分不足解锁时看到明确提示。
- 用户在驿站提问能命中知识库并输出解读，无匹配时给出引导。
- 登录用户的浏览历史可见。
- 部署后可通过公开 URL 正常访问，核心流程在桌面与移动端可用。

## 3. 范围

### 信息架构（页面路由）

| 路由 | 名称 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 科小獬主视觉 + 全站导航 + 专题/专栏/驿站入口 |
| `/ip` | 科小獬介绍页 | IP 起源、形象解读、使用规范 |
| `/columns` | 普法专栏 | 专题列表，支持主题类型 + 案例类型筛选 |
| `/columns/[slug]` | 专题详情 | 科普长文 + 常见问题（Q&A）+ 要点侧栏 |
| `/station` | 线上普法驿站 | 筛选 + 提问框 + 科小獬解读 + 推荐专题/常见问题 |
| `/quiz` | 答题中心 | 展示积分、答题入口、完成小问答赚积分 |
| `/topics` | 专题库 | 基础内容免费，拓展案例专题需积分解锁 |
| `/history` | 浏览历史 | 登录用户看过的专题与问答 |
| `/login` | 登录/注册 | 邮箱 + 密码，不启用验证码，支持游客浏览 |

### 数据模型（Supabase / Postgres + RLS）

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `profiles` | 用户资料与积分 | `id`（关联 `auth.users`）、`points`、`nickname`、`created_at` |
| `topics` | 普法专题 | `id`、`slug`、`title`、`summary`、`category`、`case_type`、`is_premium`、`premium_points`、`thumbnail`、`order` |
| `articles` | 专题科普长文 | `id`、`topic_id`、`title`、`content`、`published_at` |
| `faqs` | 常见问题 | `id`、`topic_id`、`question`、`answer`、`keywords`（文本数组） |
| `quizzes` | 小问答题目 | `id`、`topic_id`、`question`、`options`（JSON）、`correct_index`、`points` |
| `user_quiz_attempts` | 答题记录 | `id`、`user_id`、`quiz_id`、`is_correct`、`points_earned`、`created_at` |
| `browsing_history` | 浏览历史 | `id`、`user_id`、`entity_type`、`entity_id`、`viewed_at` |
| `unlocked_topics` | 已解锁专题 | `id`、`user_id`、`topic_id`、`unlocked_at` |
| `question_logs` | 提问日志 | `id`、`user_id`、`question`、`matched_topic_id`、`created_at` |

用户数据表（`profiles`、`user_quiz_attempts`、`browsing_history`、`unlocked_topics`、`question_logs`）均启用 RLS，仅本人可读写；`topics`、`articles`、`faqs`、`quizzes` 公开可读。

## 4. 核心流程

### 注册与登录

- 使用 Supabase Auth 的邮箱 + 密码模式。
- 不启用邮箱验证码，也不做图形验证码，注册后即可登录。
- 游客可直接浏览全部基础普法内容；只有登录后才开始累计积分、写入浏览历史。

### 答题积分

- 进入答题中心，完成小问答。
- 答对 +X 分（题目分值），答错不加分。
- 每道题只计一次分：后端依据 `user_quiz_attempts` 判断，防止重复刷分。
- 答完展示本轮得分与当前总积分。

### 积分解锁

- 拓展案例专题标注所需积分（`premium_points`）。
- 解锁是一种一次性消费：当用户积分大于等于所需积分时，点击解锁会写入 `unlocked_topics` **并扣减对应积分**；不足时弹出提示"积分不足，继续答题赚积分"，不做部分扣减、不产生负积分。
- 本版不处理真实支付，页面保留后续"拓展入口"占位。

### 提问 → 解读

- 用户在驿站输入问题，系统对问题做规范化（去标点/空白），再按关键词与主题匹配到 `faqs` 或 `topics`。
- 命中后以科小獬口吻输出解读，并展示关联的专题入口。
- 无匹配时给出默认引导文案（例如引导用户选择相关专题）。
- 每次提问写入 `question_logs`，为后续升级真实 AI 留存数据。

### 浏览历史

- 登录用户浏览专题详情/FAQ 时写入 `browsing_history`。
- `/history` 页展示历史列表。

## 5. IP 与视觉系统

### 科小獬 IP

- 以獬豸（独角神兽、公正象征）为原型，融入科大/科技与司法元素。
- 采用 **Q 版萌系科技感法兽** 风格：圆润亲和、科技蓝为主色、正义金/青绿点缀；独角设计为带光效的"法治天线"，并融入护盾、天平、代码块等轻量元素。
- 使用生成式插画产出主形象，另制作 2–3 个状态变体：答对鼓励、提问引导、站内提示。

### 视觉规范

- 配色：科技蓝为主，正义金/青绿点缀；页面浅色干净底，避免单一色系与"渐变紫 / 米色 / 深蓝一色"等常见同质化配色。
- 组件：按钮/操作项带图标（lucide），卡片圆角 ≤ 8px，页面区块为通栏或非卡片布局，卡片仅用于重复条目、弹窗与工具容器。
- 布局：清晰导航，移动端适配，保证文字不溢出、不遮挡，固定控件（按钮/标签/计数）尺寸稳定。

## 6. 技术架构

- **框架**：Next.js（App Router）+ TypeScript + Tailwind CSS。
- **组件**：轻量自研组件或按需使用 shadcn/ui。
- **数据库与认证**：Supabase（Postgres + Supabase Auth + RLS）。
- **字体/图标**：中文字体栈 + lucide 图标。

## 7. 部署

- 部署到 Vercel。
- 配置环境变量：`SUPABASE_URL`、`SUPABASE_ANON_KEY`。
- 首版不接入真实支付、不配置邮件推送。

## 8. 测试策略

- **单元测试**：覆盖积分计算、防重复刷分、解锁扣分/积分不足、提问匹配等核心规则。
- **浏览器自动化**：使用 agent-browser / Playwright 走查关键流程：注册登录、答题、解锁弹窗、提问解读、浏览历史。
- **视觉与交互冒烟**：部署前运行本地 dev server，检查桌面与移动端布局，无溢出/遮挡。

## 9. 第一版边界（明确不做）

- 不做真实支付、邮件推送、复杂后台、深度 SEO、短视频、用户投稿上传、多角色权限管理。
- 不接真实大模型，提问解读使用知识库匹配。

## 10. 后续扩展路径

- 将提问匹配层替换/增强为真实 AI 生成，复用 `question_logs` 中的用户问题数据。
- 支付与付费专题预留入口。
- 内容运营与后台管理、多角色权限，后续按需引入。
